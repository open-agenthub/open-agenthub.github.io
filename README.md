# Open AgentHub — Website

Marketing site for [Open AgentHub](https://github.com/open-agenthub/open-agenthub),
served via GitHub Pages.

- `index.html` — landing page
- `docs-src/` — documentation source (VitePress); `docs/` — its built output, served at
  `/docs/`. See [Documentation](#documentation) below.
- `install.sh` — all-in-one quickstart script for Linux (k3s) and macOS (Docker Desktop + k3d):
  `curl -fsSL https://open-agenthub.github.io/install.sh | sh`
- `install.ps1` — all-in-one quickstart script for Windows (Docker Desktop + k3d):
  `iwr -useb https://open-agenthub.github.io/install.ps1 | iex` (Windows PowerShell 5.1 and 7)
- `agb.html`, `datenschutz.html`, `impressum.html` — legal pages (German market)
- `support.js` — page runtime (generated by Claude Design; loads the vendored libraries)
- `vendor/` — locally hosted React, ReactDOM, Babel (no third-party CDN requests)
- `fonts/` — locally hosted fonts (no Google Fonts requests, see privacy policy)

Both install scripts deploy persistent Postgres and object storage (Garage, bootstrapped),
keep generated secrets on re-runs, and pin their own kubectl context. They install the chart
from the Helm repository `https://open-agenthub.github.io/open-agenthub` (GitHub Pages of the
main repo, `gh-pages` branch) — if that index is unreachable they fail instead of using a
stale cache. `AGENTHUB_CHART=<chart-url-or-ref>` overrides the chart, e.g. for testing a
release `.tgz`.

## Documentation

The docs site lives at [`/docs/`](https://open-agenthub.github.io/docs/) and is built with
[VitePress](https://vitepress.dev) from `docs-src/`.

```bash
cd docs-src
npm install
npm run dev      # local preview with hot reload
npm run build    # writes ../docs
```

Because Pages serves this repository straight from the branch root (no build step there),
**the built output in `docs/` is committed**. Always run `npm run build` and commit both
`docs-src/` and `docs/` in the same commit, otherwise the published site drifts from its
source.

## Deployment

GitHub Pages, deploy from branch: repository **Settings → Pages → Source: Deploy from a
branch → `main` / root**. No build step required.

**Important:** the advertised URLs (`https://open-agenthub.github.io/` and
`…/install.sh`) require this repository to be named **`open-agenthub.github.io`**
(GitHub Pages root site). As `open-agenthub/pages` it would be served under
`…/pages/` instead — rename the repository accordingly. All in-page links are
relative, so both layouts render fine.

## Landing page and SEO

The homepage is static semantic HTML with `landing.css`. It does not load the
Design runtime, React or Babel. The runtime and vendor files remain available
for the other existing pages. All fonts remain locally hosted.

The homepage includes a descriptive title, description, canonical URL,
Open Graph/Twitter metadata and SoftwareApplication JSON-LD. `robots.txt` points
to the root `sitemap.xml`, which lists the homepage and public guide pages.
Update that sitemap when documentation routes change; do not add transactional
or error pages. Indexing and rankings still need verification in Search Console;
no ranking or conversion improvement is claimed from these changes alone.

`assets/social-card.html` is the editable source of `social-card.png` (1200×630).
The workflow illustration on the homepage is explicitly illustrative, not a
customer outcome or screenshot. Do not add unverified usage or productivity
claims. Enterprise pricing is not advertised; the edition distinction is stated.

Validation with Node (no package install needed):

```bash
node scripts/check-site.mjs
```

Optional browser rendering (requires an existing Chromium CDP endpoint; uses
its active tab, so use a dedicated preview browser):

```bash
node scripts/render-preview.mjs http://BROWSER_HOST:9222
```

This embeds local CSS, fonts and icons for preview, regenerates the social card,
checks heading/anchor semantics and horizontal overflow at 1440, 390 and 320px,
and saves viewport screenshots under `/tmp/agenthub-<width>.png`. It does not
publish the website. Review screenshots before deployment. GitHub Pages serves
`main`, so pushing changes there publishes them.

## Blog

`blog/index.html` lists the published articles; each article is a plain HTML
`blog/<slug>/index.html` using the existing local fonts and landing-page tokens
plus `blog/blog.css`. Static HTML keeps articles readable and indexable without
adding a framework or a client runtime. Update the homepage entry points and
`sitemap.xml` when adding an article. Use its public directory URL as canonical.

The first article is based on the reviewed marketing draft at commit b7f7809
in `open-agenthub/marketing`, branch `marketing/blog-first-article`. Publication
excludes internal editorial notes. It covers a proposed first experiment, not a
customer result; installation and transfer facts were checked against the existing
website guides. New release-sensitive statements require their own source check.

Validate local links, canonical metadata and headings, then inspect desktop/mobile
rendering. Publishing these routes does not establish Google indexing or rankings.

The PHP security-update article at `blog/wordpress-php-security-update/` includes
its exact reviewed MP4, local poster, English WebVTT and transcript. Native HTML
video keeps it usable without a third-party player or login. A public YouTube link
can be added after the production uploader verifies it; never ship placeholder
video IDs or embed a private review URL. The article distinguishes the actual
PHP development-server lab from production PHP-FPM/Apache and an overnight run.

The PHP article now offers its verified public YouTube video through a
click-to-load player (`blog/youtube-player.js`), with the original native player
as an alternative. No YouTube player request occurs until the reader loads it.
Check the exact public video ID and the native caption fallback when editing.
