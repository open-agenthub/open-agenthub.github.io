Choosing a model ​

The Model field in the New session, Edit session and Duplicate session dialogs sets the model a session starts on. Below the field the dialog lists the models the selected account offers, with the controls each one has (reasoning effort levels, context size, image input, fast mode) as the agent's own CLI reports them.

Edition: Community · Who: the session owner chooses; collaborators can refresh a shared session's list; viewers of a shared session (Enterprise) only read it.

How to use it ​

  1. Pick the agent, the billing and, for a subscription, the account.
  2. Click a model in the list, or type any model id. Leave the field empty to start on the CLI's default.
  3. Refresh asks the agent's CLI again, through one of your running sessions on the same account.

Changing the model in Edit session takes effect at the session's next start. To change it in the middle of a conversation, use the Model button of the running session (below).

Switching the model of a running session ​

The session bar in the Workspace shows the model the session runs on (CLI default until one was chosen). Click it to pick another model from the account's list, or type an id, then press Switch or Save for restart. The picker says which of the two happens before you press it.

Edition: Community · Who: the session owner and, in a shared session (Enterprise), collaborators. Viewers see the current model but cannot change it.

AgentWhat happensThe conversation

A switch that happens right away is done by the agent's own CLI, and the picker shows the CLI's confirmation, for example Now on gpt-6-luna. The agent said: "Model changed to gpt-6-luna". The model is also stored with the session, so a later restart stays on it.

When a switch is refused ​

A model is only switched between turns. The picker refuses, and says why, while:

  • the agent is working on a turn — wait until it has finished;
  • a question or an approval is open — answer or decide it first;
  • a menu is open in the agent terminal — close it first;
  • text was typed into the agent terminal and not sent — send it or clear it (Ctrl+U).

Nothing is queued: press Switch again once the agent is ready.

Other messages you may see: The agent refused this model (Codex accepts only ids from its own list while it runs), The agent did not confirm the switch (look at the agent terminal), and The session is not running (OpenCode and OpenClaw switch only in a running session; Claude and Codex save the model for the next start instead).

Limits ​

  • Claude and OpenClaw take any id without checking it; a model the account cannot use fails at the next turn.
  • OpenCode's picker finds models by name. If two models in the list share a name, switch in the agent terminal instead.
  • Cursor's switch has not been tested with a real Cursor account yet.
  • A session started on an older runtime image has no live switch; update its runtime image, or change the model in Edit session for the next start.

Where the list comes from ​

AgentHub does not keep its own model list and does not ask the providers itself. The list is what the agent's CLI reports inside a session pod, with that session's login or key, and it is stored per user and per account:

AgentSourceChecked against the account?
ClaudeClaude Code's own model listYes for a subscription login (it shapes the list by plan); not for an API key
CodexCodex's model listYes for a subscription login; not for an API key
Cursoragent models, the account's listYes
OpenCodeOpenCode's models for the providers you are logged in toNo, it is a catalogue
Own endpointThe endpoint's /models, asked from the session podYes, it is the server's own list
OpenClaw—Type the model id; OpenClaw picks its model from the API key

A running session reports its list shortly after it starts, so the dialog knows an account once any session has run on it.

StatusMeaning

Could not read this account's modelsThe CLI is not signed in, the key was refused or the endpoint could not be reached. Type an id instead.

A model you chose stays chosen even when a later list no longer contains it; the dialog marks it as not listed instead of switching models or accounts for you.

Limits ​

  • Refresh needs a running session on the same account. Without one the dialog says so; no pod is started just to read a list.
  • For an own endpoint the hub never contacts the endpoint itself. Its list comes from a session pod on that endpoint.
  • Cursor's list was not yet tested against a real Cursor account; if its output cannot be read, the dialog reports an error and the field stays free text.
  • Viewers of a shared session see the session's stored list and chosen model, without any account name, e-mail or key, and cannot refresh it.
